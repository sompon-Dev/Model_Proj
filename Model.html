อธิบายโมเดลค้นหาเพลง ตั้งแต่สร้างจนถึงค้นหา

⚠️ โหลดตัวสร้างผัง (Mermaid) ไม่ได้ ไฟล์นี้ต้องต่ออินเทอร์เน็ตตอนเปิดครั้งแรก กรุณาตรวจสอบการเชื่อมต่อแล้วรีเฟรชหน้านี้

2คำศัพท์พื้นฐาน (อ่านก่อนจะเข้าใจง่ายขึ้น)

Embedding / Vectorชุดตัวเลขที่ "แทนความหมาย" ของข้อความ ในระบบนี้ 1 ข้อความ = ตัวเลข 768 ค่า ข้อความที่ความหมายใกล้กันจะได้ตัวเลขใกล้กัน
โมเดล (Model)โปรแกรมที่เรียนรู้มาแล้วจากข้อความจำนวนมหาศาล ทำหน้าที่แปลงข้อความเป็น vector เราใช้ตัวสำเร็จรูป ไม่ได้สอนเอง
Indexตารางที่เก็บ vector ของทุกเพลงไว้ล่วงหน้า ตอนค้นหาจะได้ไม่ต้องแปลงเนื้อเพลงใหม่ทุกครั้ง (ไฟล์ songs_embeddings.pt)
Tokenชิ้นส่วนย่อยของข้อความที่โมเดลอ่าน อาจเป็นคำหรือส่วนของคำ โมเดลรับได้สูงสุด 512 token ต่อครั้ง
Normalizeปรับ vector ให้ "ความยาวเท่ากับ 1" เพื่อเทียบกันเฉพาะ "ทิศทาง" (ความหมาย) ไม่สนว่าข้อความยาวหรือสั้น
Cosine Similarityคะแนนความคล้ายของ vector สองอัน วัดจากมุมระหว่างกัน ยิ่งใกล้ 1 ยิ่งคล้าย เมื่อ vector ยาว 1 ทั้งคู่ คะแนนนี้เท่ากับ dot product
Top-Kเลือกเพลงที่คะแนนสูงสุด K อันดับแรก ค่าปัจจุบันใน Search.py คือ top_k=11
Dot product / matmulคูณตัวเลขแต่ละคู่แล้วรวมกัน matmul ทำแบบนี้กับทุกเพลงพร้อมกันในคำสั่งเดียว จึงเร็ว

ภาพประกอบ: ทำไมเทียบด้วยมุมจึงหาเพลงที่คล้ายได้

เมื่อ normalize แล้ว ทุก vector ยาวเท่ากัน จึงเรียงตัวอยู่บนวงกลม (ในความจริงเป็นทรงกลมใน 768 มิติ ภาพนี้ย่อเหลือ 2 มิติให้เห็นง่าย) ยิ่งมุมระหว่างสองจุดแคบ ยิ่งคล้ายกัน

ในภาพ: เพลง A และ B อยู่ใกล้ ★ (มุมแคบ) จึงได้คะแนนสูง เพลง C, D, E อยู่ไกล (มุมกว้าง) คะแนนต่ำ ตำแหน่งในภาพเป็นตัวอย่างสมมติ ไม่ใช่ข้อมูลจริง

Top-K ปัจจุบันtop_k=11 ใน Search.py

8ข้อสังเกตที่อาจกระทบคุณภาพผลการค้นหา

ข้อเหล่านี้ยังไม่ได้ทดสอบว่ากระทบผลจริงมากแค่ไหน แต่เป็นจุดที่ควรรู้ และเป็นแนวทางปรับปรุง

  1. เนื้อเพลง 22 จาก 79 เพลงถูกตัดท้าย โมเดลอ่านได้ไม่เกิน 512 token ส่วนที่เกินไม่ถูกนำมาคิด vector ของเพลงเหล่านี้จึงแทนความหมายเฉพาะช่วงต้นเพลง คำค้นที่ตรงกับท่อนท้ายอาจไม่เจอ
  2. ไม่ได้ใส่ prefix ของโมเดล E5 ตามคู่มือของโมเดลตระกูล E5 ข้อความฝั่งคำค้นควรขึ้นต้นด้วย "query: " และฝั่งเนื้อเพลงขึ้นต้นด้วย "passage: " ตอนนี้ทั้ง Buildindex.py และ Search.py ส่งข้อความเปล่าเข้าไป
  3. รูปแบบข้อความสองฝั่งไม่เหมือนกัน เนื้อเพลงใน index ผ่านการตัดคำ (มีเว้นวรรคระหว่างคำ) แต่คำค้นส่งเข้าไปเป็นข้อความดิบ ตัวอย่างจากเครื่องนี้: "ฉัน รัก เธอ" ถูกตัดเป็น token ▁ฉัน ▁ รัก ▁เธอ ซึ่งมี token เว้นวรรค (▁) เพิ่มเข้ามา ส่วนคำค้นดิบจะไม่มี
  4. ยังไม่ได้ใช้ genres / moods กรองผล แอปส่งสองค่านี้มา แต่ API.py ยังไม่ได้นำไปใช้
  5. ไม่ได้ fine-tune โมเดล ใช้โมเดลสำเร็จรูปตามที่มี ถ้าอยากให้เข้าใจเนื้อเพลงไทยดีขึ้น มีทางเลือกคือเปลี่ยนโมเดล (เช่น BGE-M3 ที่รับข้อความยาวได้ 8192 token) หรือแบ่งเพลงเป็นท่อนแล้วสร้าง vector ทีละท่อน
  6. Index เป็นไฟล์นิ่ง เพิ่มเพลงต้องสร้างใหม่ทั้งชุดและรีสตาร์ท API.py (ดูหัวข้อ 6)
ทำไมข้อ 1-3 สำคัญ: ทั้งสามข้อเป็นการปรับที่ไม่ต้องเปลี่ยนโมเดลเลย เสียแค่สร้าง index ใหม่ ถ้าอยากทดสอบว่าข้อไหนช่วยจริง ควรเตรียมคำค้นสัก 20-30 ข้อที่รู้คำตอบ แล้ววัดว่าเพลงที่ถูกอยู่ใน Top-K กี่ครั้ง ก่อนและหลังแก้
